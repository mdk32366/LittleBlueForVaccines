## v0.2-a client metrics (app/, PR 5): proposed, numbering per the v0.2 spec

Note (Q-M3 closed, Architect ruling 11/13): the national column is always shown next to the state column, whatever the BENCHMARK toggle, because the client's ask compares with national AND with state; D-0034 (national file public-real) keeps it benchmark-only and the toggle still governs F1 and F6.
- **AS-0043 (comparators):** national = the whole national file pooled; state = synthetic in-state peers, AS-0031 (in-state peers), their components summed. The national file has no state. A1's state figure (amended, Architect ruling on PR 5) is the system's share of the state total INCLUDING the system, system ÷ (system + pooled in-state peers), a fraction bounded 0 to 1; the in-state peer median dollars (A1M) are shown next to it for scale. Its national figure is the system's share of national dollars. Medians (A7–A9 state) are over the peers' per-system counts, a peer without a row in a specialty counting as zero.
- **AS-0044 (ratio rule):** a ratio is shown when the denominator is at least 50 net doses and the numerator is at least 0. Denominator ≤ 0 gives "undefined", under 50 gives "insufficient volume", a negative numerator gives "net returns"; never inf, never negative. Index = system ÷ comparator × 100, only when both are values and the comparator is above zero. Shares (A1, A11) give "undefined" on a total ≤ 0 and "net returns" on a negative part. A10 (babies, the client's heuristic) gives "undefined" when the total estimate is ≤ 0 and "inconsistent (private exceeds total)" for public and private share when private exceeds total; total and private are still shown as estimates. R7 applies the ratio rule to each of its three parts over their sum.

## v0.2-d visit store + FAKE Salesforce payload record (app/, PR 8): proposed, numbering per the v0.2 spec
AS-0045 to AS-0047 belong to v0.2-b/v0.2-c, AS-0051 and AS-0052 keep their spec reservations, and AS-0053 to AS-0056 are the v0.2-b client-email entries, so the two new entries here take AS-0057 and AS-0058.
- **AS-0048 (visit key, exact lookup):** a visit is keyed by `rep|YYYY-MM-DD|SYNCPnnnnnn`. The rep part is casefolded and trimmed, with inner whitespace collapsed; the system id is upper-cased. Lookup matches that exact key and nothing else: no prefix, no LIKE, no date range, no name search. The store exposes no list-all or enumerate function (T-0048 pins the public API). This replaces the spec's filter-style lookup and its "Replace existing visit" tick box: a re-save of the same key is allowed and appends a payload version (AS-0057 (sf payload is a database record, not a send)).
- **AS-0049 (sf payload field names):** the payload holds one sObject Tree (Composite Tree) request body per root type, side by side under `trees`. `trees.Event` has one Event (Subject `Vaccine rep visit – <system>`, ActivityDate, StartDateTime, DurationInMinutes, Description, What = Account by external id `LB_System_Id__c`, `LB_Rep_Key__c`, `LB_Visit_Key__c`, `LB_Synthetic__c`), with nested `Talking_Point_Outcomes__r` child records of type `Talking_Point_Outcome__c`, one per talking point: `Talking_Point_Key__c`, `Point_Text__c`, `Metric_Value__c`, `Benchmark_State__c`, `Benchmark_National__c`, `Addressed__c` (Raised / Partially / Not raised), `Customer_Response__c` (Positive / Neutral / Negative / Objection), `Quality_Score__c` (1–5), `Evidence_Quote__c`, `Follow_Up__c`. `trees.Task` has one Task per non-empty follow-up. `Metric_Value__c`, `Benchmark_State__c` and `Benchmark_National__c` carry the provider's value as a JSON number, or null when it is None, NaN or infinite; a display string from the fallback stays text. Talking_Point_Key__c is the provider key, for example `fixed.A1`, `must.R2`, `question.F2` or `must.none`. Top-level `lb_marker` is the constant `FAKE-SYNTHETIC`, and every root record's Description starts with it. The schema is `app/brief/schemas/visit_payload.schema.json` (JSON Schema 2020-12, `additionalProperties: false`), checked with `jsonschema`. Every field ending in `__c`, and the child relationship name, is a proposal that has not been checked against any org. A real org can't put a custom lookup on Event, so an org build would need a parent object (for example a custom Visit object) in place of the Event as the outcomes' parent. An sObject Tree body also doesn't support an external-ID reference for a lookup field, so the What = Account by `LB_System_Id__c` on the Event (and on each Task) would have to be resolved to an Account Id first (or the records created through a different request) before a real org would accept it. This shape replaces the spec's §6 sObject Collections Task.
- **AS-0050 (visits DB path):** `LB_VISITS_DB`, default `<repo>/data/visits.db`. `data/visits.db*`, `data/*.db` and `data/backup-*` are gitignored. Tests always use a temporary path. Backups use `python -m brief.visits backup DEST [--db PATH]` (the sqlite3 online backup API, mode 600). A live deploy needs a writable visit DB path: in a read-only container the default path can't be opened, so the Visit record tab shows "Not saved" (and "Lookup failed" for a lookup) and stores nothing, while the rest of the tab and app keep working (T-0060). The Deploy-2 data/ mount provides the writable path.
- **AS-0057 (sf payload is a database record, not a send):** the owner, 2026-11-13 14:26 PT: "No actual send. Just create the payload and place it into a database record." And at 12:20 PT: "all sessions saved to a database." Saving a visit builds the payload, validates it and appends it to `sf_payloads` (version n+1, sha256 of the canonical JSON). Rows are append-only: SQLite triggers refuse UPDATE and DELETE. Nothing is posted anywhere, there is no Salesforce client, and the payload and store modules import no HTTP or socket library (T-0049). No UI action is labelled "Send". A visit file download stays as a second route.
- **AS-0058 (open visit store, no passcode):** no passcode was chosen for the visit store, and the owner accepted the risk of an open demo store. Anyone who can reach the app can save a visit, or read one if they know its exact rep, date and company. Mitigations: a banner on the tab (synthetic data only, no PHI, no Salesforce connection); exact-key lookup only, with no list-all, so stored visits can't be enumerated from the UI (AS-0048 (visit key, exact lookup)); notes capped at 8,000 characters; 30 saves per browser session; and every record marked FAKE-SYNTHETIC.
## v0.2-c voice notes (app/, PR 7): numbering per the v0.2 spec
AS-0047 keeps its spec reservation. AS-0057 and AS-0058 are taken (v0.2-d), so the new privacy entry takes AS-0059.
- **AS-0047 (STT engine and model):** offline speech-to-text with faster-whisper 1.2.1 (ctranslate2 4.9.0) on CPU: `compute_type="int8"`, `cpu_threads=2`, `beam_size=1`, `language="en"`. The default model is **small.en**; the owner, 2026-11-13 12:20 PT: "The more accurate one is what I picked." base.en is the swap (`LB_STT_MODEL=base.en`) and tiny.en the low-resource fallback. The model loads only from a local directory (`LB_STT_MODEL_DIR`, default `<repo>/models/faster-whisper-<model>`, gitignored) with `local_files_only=True`, so nothing is downloaded at runtime; a deploy also sets `HF_HUB_OFFLINE=1`. The model loads lazily on the first recording and is cached per process (`st.cache_resource`). The recording is decoded in memory with stdlib `wave` + numpy to float32 at 16 kHz (16-bit PCM only; stereo is mixed down; any other rate is refused), and faster-whisper is handed the array, never a path (F-0018 (PyAV path decode fails)). `LB_STT=off`, a missing package or a missing model hides the recorder with "voice unavailable: <reason>"; any decode or engine error falls back to typed notes with a note. The voice packages are optional (`app/requirements-voice.txt`); CI runs the Stub only.
- **AS-0059 (raw audio is not kept):** the recording from `st.audio_input` is read in memory, transcribed and dropped. It is never written to disk, the visit store or the payload; only a sha256 of it stays in the browser session, so one recording is transcribed once. What is saved is the notes text after the rep has checked and edited it, the same field as typed notes. This is the spec's proposed D-0038 (no raw audio kept), held as an assumption until the owner words that decision.

## GATE 2 path B: schema_v1 (spec v1.1)
- **Supersessions:** AS-0014 (synthetic counterparty) is superseded by D-0043 (real names in generated data) and D-0044 (real manufacturer as the contract party); AS-0015 (fictional product ids) is superseded by D-0043. Both still describe stub v0.
- **AS-0060 (EXH1 is an invented schedule):** each system gets one EXH1 "Purchasing profile schedule", a contract document stamped synthetic (D-0022 (fake data)) and marked (D-0044). Its figures come from the synthetic sales file and the national file; it uses no RNG (T-0075).
- **AS-0061 (EXH1 uses the app's windows):** EXH1 uses the app's FULL window (202410-202609), the R7 season (202510-202603) and the app's ratio, share and status rules; tier and commitment terms keep T12 (AS-0024). Parity with the app is T-0064.
- **AS-0062 (state pools are aggregates):** in-state peer pools inside a train system's EXH1 include held-out systems' sales as aggregates (sums and medians) only. This is not a split leak (D-0025).
- **AS-0063 (blank subsidiary is parent-owned):** a blank subsidiary means the site is owned by the parent (the app's rule). It is not invented.
- **AS-0064 (same-season switching):** switching is the brand (and party-manufacturer) share within a class across the same-season windows, at 15 points (the Q7 default), each window floored at zero like the app's F5. Interim until F14 (PR 6b) settles the app rule; T-0064 excludes §13 until then.
- **AS-0065 (R4 stays interim):** R4 keeps its source value, labelled interim (AS-0053).
- **AS-0066 (national A6-A9 stay not available):** the national file has no system, subsidiary, site or state columns, so national A6-A9 are "not available" with the app's reason text, never an invented number (T-0069).
- **AS-0067 (synthetic counterparty retired):** superseded by D-0044 (real manufacturer as the contract party).
- **AS-0068 (national figures pooled only):** gen/out holds pooled national totals only, never a national row (T-0065).
- **AS-0069 (accepted risk: real manufacturer as the party to invented terms):** gen/out is in a public repository. Invented rebates, fees, share floors, exclusivity, commitments and proposals are attributed to real manufacturers by name, and a reader who ignores the markers could take them for real commercial terms. The owner accepted this risk (D-0044); scope, the owner: "This is a proof of concept, and it is for demo purposes only in the context of a class project.  This will not be used by the public in any way shape or form." Mitigations: the fixed header and footer marker on every document and on every Contract and Proposal leaf, plus the STAMP (D-0022); the manifest flag and the per-row `terms_invented`; T-0073, which fails the build if any marker is missing; the pricing, clinical and real-data refusals (T-0068). No real contract data is used: the terms are drawn from the seed, and only the party and brand names come from the file.
